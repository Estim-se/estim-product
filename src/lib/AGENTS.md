- Analyse tender files one at a time through authenticated server functions, with atomic per-run/document reservations and immutable file metadata; this prevents overlapping runs and keeps analysis tenant-scoped without touching conversation modules.
- Tender PDFs are sent as documents after exact page counting; Office files are extracted locally and unknown print-page counts remain null rather than invented.
- Tender Claude calls use the required streaming Lovable Messages gateway and a server-held gateway key, isolated from the existing reply transport because new Supabase Edge functions are blocked by the platform.
- Run AF-first key-data, risk and question extraction separately with two bounded retries for incomplete/schema-invalid output and transient failures; save each completed step so recovery never repeats successful work.
- Use call-local risk checklist indexes and recover broken internal references without dropping source-backed risks; this prevents merged or sorted risks from invalidating analysis.
- Extract quantity operands and sum-of-products rules in a separate third tender step; fixed-point arithmetic calculates totals, assumptions remain separate, and current-run company-private storage rejects stale results.
- Keep company cost settings and AI bindings separate; only approved catalog types enter deterministic totals, while unmatched posts remain visible as proposals until approved.
- Generate tender exports only in browser actions from existing company-authorized reads; Excel formulas mirror the cost helper and prepared blobs retain click activation for downloads without new storage or AI calls.
- Run tender analysis as a server-side job (`tender_jobs`): one step per hop under a DB lease with a per-job token; published hops are posted by pg_net to `/api/public/tender-job`, dev runs hops in-process, and resume skips done steps.
- Tender AI validation flags unverifiable figures (Låg, "Källa saknas – kontrollera", Antaganden) instead of failing the step.

- Match every confirmed and assumed tender post semantically against the company catalog; only unmatched or unresolved-quantity rows require manual inputs. Room recipes are editable company JSON, document counts override recipes, and row-wise area rounding is calculated in code.
- Recalculate quantities and costs through a company-authorized private job scheduler using the existing analysis run; its two-step plan leaves classifications and insights untouched.
- Cache physical PDF-page chunks and Office cell text by company/file hash/reading version, and cache step results by source/model/context/settings fingerprints; identical reruns reuse outputs while explicit rereading invalidates caches.
- Keep the electrical coverage audit in a browser-safe pure helper shared by the tender page, PDF and Excel; proposals and unresolved counts cannot imply priced coverage.
- Verify every Anbud source through `tender-source-verification.ts`: PDF by physical page, spreadsheets by file/sheet/row (model page dropped, location recorded); keyword matching of post names strips negated phrases via `tender-negation.ts` so exclusions never decide a post's meaning.
- Bedrooms are whole rok-1 ("3 rok" = three rooms and a kitchen) or read from a column headed sovrum; a half room ("3.5 rum") is a separate Halvrum with its own editable recipe line; PDF quotes are accepted on the correct physical page when wording differs but every number matches; object/room counts are operands only, never cost rows; each risk call's checklist schema requires one status per assigned area.
- Standard posts are built in code (`tender-standard-posts.ts`): one post per recipe room type and equipment from the object-list room count, smoke detectors from a documented per-area rule, and documented per-apartment rules. The model overrides a room only with a documented, sourced count; rules lacking data fall back to the recipe as an assumption; missing scope is noted, never dropped silently.
- Documented figures times verified object-list counts are Hög (a model note becomes an assumption, not a demotion). An applying index regulation (e.g. EM-index) is Normalt, never a risk; a risk states the documented values and AF code from its cited AF section.
- Spreadsheet quotes (e.g. a summarised time plan) are verified on the best window of consecutive rows, with Excel date serials matching ISO dates; a quote cited with the wrong document moves to the single document that contains it. A selection filtered on premises counts premises rows. Insurance requirements of at least 10 MSEK are always a risk with the amount; only an explicitly missing index regulation is a risk.
- Recipe posts never fall back to 1: the object list is the room selection or detected type column covering the most rows; a recipe term without a verified room count, or a vardagsrum/hall/kök post below the apartment count, is flagged Låg outside the total. Verification includes fresh tenders (new document ids, fresh model answers), not only cached reruns.
- Requirements engine (flag ANBUD_REQUIREMENTS_ENGINE=1, off by default): the model lists requirements per unit with sources (`tender-requirements-ai.server.ts`); code counts every unit from the object model (`tender-object-model.ts`) and drawing type codes (`tender-type-codes.ts`) and builds the quantities (`tender-requirements.ts`). The model never selects cells or counts objects.
- Requirements engine counts rooms per room type from a room schedule (`tender-room-list.ts`, unit `rumstyp`) for non-residential buildings; counter sockets per length use the kitchen recipe; kitchen/bathroom posts stated per apartment count kitchens/bathrooms from type codes; "lokal rivning" never counts premises; a note states how many type codes were read and matched.
- Requirements engine, round 2: a stated fixed quantity always wins; an area divisor per apartment is per started area; options are their own rows (Saknar pris until given their own price); overlapping requirements for the same equipment and unit merge (generic meanings never), one-off posts on the same catalog type count once, and a per-apartment catalog type counts apartments; type codes link through list-validated number/area candidates.
- Drawing type codes: digits after K/B/W/T are type numbers (count the letters). Without a number or area next to the code, apartments link by room count and the floors the drawing page states ("Våningsplan 1-6", attic = top floor), only when the codes agree; everything derived from drawings is Antagen with the reason. A complete-package catalog type ("komplett") is priced once per unit; per-apartment catalog conversions are Antagen.
